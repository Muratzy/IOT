# 串口和数据协议

## 物理参数

- USART1：9600 baud、8 data bits、1 stop bit、no parity。
- STM32 PA9 TX -> CH9121 RX。
- STM32 PA10 RX <- CH9121 TX。
- 两者 GND 共地。
- 命令和状态帧都以 `\r\n` 结尾，Python 以 `\n` 拆行并去掉 `\r`。

## STM32 -> Python v3 状态帧

```text
T1=+21.1,S1=0,T2=+21.2,S2=0,F=00.35,SF=1,P=0000933,SP=1,A=0408,D=+0005,M=060,MS=1,MT=0000001750
```

| 字段 | 含义 | 单位/取值 |
|---|---|---|
| `T1`,`T2` | 两路温度 | °C，1 位小数 |
| `S1`,`S2` | DS18B20 状态 | 0 OK，1 BUSY，2 NO_DEVICE，3 CRC，4 PARAM |
| `F` | 瞬时流量 | L/min，2 位小数 |
| `SF` | 流量状态 | 0 WAIT，1 OK，2 TIMER_ERROR |
| `P` | 压力 | Pa，整数 |
| `SP` | 压力状态 | 0 WAIT，1 OK，2 ADC_ERROR，3 SENSOR_ERROR |
| `A` | 当前平均 ADC | 0~4095 |
| `D` | 当前 ADC - 零点 ADC | 带符号计数 |
| `M` | 水泵实际占空比 | 0~100 |
| `MS` | 水泵切片状态 | 0 IDLE/STOP，1 RUNNING，2 DONE |
| `MT` | 水泵剩余时间 | ms |

`NETWORK_SendSensorData()` 负责格式化这一行。它的输入是 `NETWORK_SensorFrame`，由 `main.c` 每 250 ms 填充。

## Python -> STM32 水泵命令

```text
PUMP=60,TIME=2000
```

- `PUMP` 是 0~100 整数。
- `TIME` 是 0~3600000 ms。
- `PUMP=0` 时时间应为 0，表示立即停泵。
- `NETWORK_ReadPumpCommand()` 要求格式严格匹配，多余字符、超范围或超长都会拒绝。

## STM32 -> Python ACK

```text
PUMP_ACK=60,TIME=2000,OK=1
```

- `OK=1`：命令格式合法并已交给水泵逻辑。
- `OK=0`：命令无效。
- ACK 表示 STM32 接收并接受，实际运行状态还要看后续状态帧的 `M/MS/MT`。

## USART1 中断接收逻辑

1. `NETWORK_Init(&huart1)` 保存句柄并调 `HAL_UART_Receive_IT(..., 1)`。
2. `HAL_UART_RxCpltCallback()` 每收到一个字节运行。
3. 遇到 `\n` 时把当前缓冲区标记为完整行。
4. 超过 `NETWORK_RX_LINE_SIZE=64` 则丢弃整行，直到下一个换行。
5. `NETWORK_ReadPumpCommand()` 在主循环中复制完整行后再解析，避免在中断中做复杂工作。
6. `HAL_UART_ErrorCallback()` 清理错误并重新开启接收。

## 扩展一个上传字段

假设增加液位 `L`：

1. `NETWORK.h`：在 `NETWORK_SensorFrame` 增加字段。
2. `main.c`：在 `network_send` 周期块里填充字段。
3. `NETWORK_SendSensorData()`：把 `L=...` 加到格式串，确保发送缓冲区足够。
4. Python `latest`：增加默认键。
5. Python `parse_frame()`：解析 `L`。如果希望兼容旧固件，不要立即把 `L` 放入“必须字段集合”，可使用可选解析。
6. `dashboard.html -> render(data)`：把数值写入对应 DOM。
7. CLI `render()`：如果需要终端显示，同步增加。

## 协议调试顺序

1. 先看 Python 窗口的原始 `[RX]`。
2. 再看 `/api/data` 中的 `raw`、`frame_version`和 `received_frames`。
3. 最后看前端。

如果 `[RX]` 行完整但出现 `[WARN] 无法解析这一帧`，问题在字段名、数值类型或 Python `parse_frame()`，不是网页。

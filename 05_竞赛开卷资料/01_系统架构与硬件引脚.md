# 系统架构与硬件引脚

## 数据和控制方向

```text
DS18B20 x2 / 流量脉冲 / 压力 ADC
                 │
                 ▼
STM32F401 采集 -> OLED 本地显示
                 │ USART1 状态帧
                 ▼
              CH9121
                 │ TCP 1000
                 ▼
Python 桥接 -> HTTP 8000 -> dashboard.html / CLI
                 │
                 └─ POST /api/pump -> CH9121 -> USART1 -> Pump_Task -> MOTOR
```

## 引脚表

| 功能 | STM32 引脚 | CubeMX/外设 | 代码入口 |
|---|---|---|---|
| 温度 T1 | PB6 | GPIO 开漏，单总线 | `DS18B20_ReadTemperature(B6_GPIO_Port, B6_Pin, ...)` |
| 温度 T2 | PB7 | GPIO 开漏，单总线 | `DS18B20_ReadTemperature(B7_GPIO_Port, B7_Pin, ...)` |
| 流量 | PA0 | TIM2_CH1 外部时钟，Pull-up | `WATER_Update()` |
| 压力 | PA1 | ADC1_IN1，84 cycles | `PRESSURE_Update()` |
| 水泵 PWM | PA6 | TIM3_CH1 PWM | `MOTOR_SetDuty()` / `MOTOR_Slice()` |
| 水泵方向脚 | PA7 | GPIO Output | 始终置低，单向水泵 |
| OLED SCL | PB10 | I2C2_SCL / AF4 | `OLED_WriteCommand/Data()` |
| OLED SDA | PB3 | I2C2_SDA / AF9 | `OLED_WriteCommand/Data()` |
| CH9121 TX | PA9 | USART1_TX | `NETWORK_SendSensorData()` |
| CH9121 RX | PA10 | USART1_RX + IRQ | `HAL_UART_RxCpltCallback()` |
| 调试烧录 | PA13/PA14 | SWDIO/SWCLK | Keil/J-Link |

## CubeMX 关键配置

- System Clock：84 MHz。
- APB1：42 MHz，APB1 Timer Clock：84 MHz。
- ADC1：Channel 1，12 bit，Sampling Time 84 cycles。
- TIM2：32 bit 计数器，CH1 作外部脉冲时钟，输入滤波值 4。
- TIM3：PSC=5，ARR=57343，CH1 PWM。PWM 频率约为 `84 MHz / (5+1) / (57343+1) = 244 Hz`。
- USART1：9600 baud，8 data bits，1 stop bit，no parity，开 USART1 IRQ。
- I2C2：7 bit 地址，OLED 地址宏为 `(0x3C << 1)`。

## 任务周期

| 任务 | 当前周期 | 作用 |
|---|---:|---|
| `Temperature_Task()` | 750 ms | 读 T1/T2，刷 OLED 第 1 行 |
| `Pressure_Task()` | 100 ms | 采 ADC、滤波，刷 OLED 第 3/4 行 |
| `Water_Task()` | 100 ms | 计脉冲、算流量，刷 OLED 第 2 行 |
| `Pump_Task()` | 每次 while | 收命令、更新非阻塞定时水泵 |
| `NETWORK_SendSensorData()` | 250 ms | 向 CH9121 发 v3 状态帧 |
| 网页 `refresh()` | 250 ms | GET `/api/data` |
| 图表 `refreshCharts()` | 2000 ms | 从本地历史数据重画图表 |

## 修改引脚时

1. 先在 `Lunar/Lunar.ioc` 用 CubeMX 改引脚和外设。
2. 生成代码后检查 `Core/Src/stm32f4xx_hal_msp.c`、`Core/Inc/main.h`和 `Core/Src/main.c`。
3. 同步修改 `Lunar/APP/` 中直接写死的 GPIO/TIM/ADC 句柄。
4. 全局搜索旧引脚，例如改 PA1 后搜索 `GPIO_PIN_1`、`ADC_CHANNEL_1`和 `ADC1_IN1`。

## 重新生成代码的保护范围

- `main.c` 中的 include、变量、函数原型、任务实现、初始化调用和 while 内容要放在对应 `USER CODE` 区域。
- `Lunar/APP/*.c` 和 `Lunar/APP/*.h` 是独立文件，CubeMX 不会改它们。
- CubeMX 会重写 `MX_ADC1_Init()`、`MX_TIM2_Init()`、`MX_TIM3_Init()`、`MX_USART1_UART_Init()` 等自动生成函数，应优先从 `.ioc` 修改参数。

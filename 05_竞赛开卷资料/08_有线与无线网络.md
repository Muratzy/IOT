# 有线与无线网络

## 共用的 CH9121 参数

| 参数 | 值 |
|---|---|
| 模式 | TCP CLIENT |
| DHCP | 关 |
| 模块 IP | `192.168.1.200` |
| 子网掩码 | `255.255.255.0` |
| 网关 | `192.168.1.1` |
| 目标 IP | `192.168.1.142` |
| 目标端口 | `1000` |
| 串口 | `9600 8N1`，无校验 |
| RX 打包长度 | `1024` |
| RX 打包超时 | `0` |

有线与无线使用相同的 CH9121 参数，不需要来回改模块。

## 无线方案

```text
CH9121 --网线--> 路由器 <--Wi-Fi-- 电脑 192.168.1.142
```

- 路由器 LAN 必须是 `192.168.1.0/24`。
- 电脑 Wi-Fi 地址必须与 CH9121 目标地址一致。
- 如果路由器 DHCP 把电脑分配成了别的地址，CH9121 会一直连旧目标。比赛前应在路由器中给电脑 Wi-Fi MAC 绑定 `192.168.1.142`。
- 运行 `04_上位机与调试/tcp_web_bridge_192.168.1.142.py`。

## 有线直连方案

```text
CH9121 192.168.1.200 --网线--> 电脑以太网 192.168.1.142
```

双击：

```text
有线接收/启动有线直连.cmd
```

脚本会：

1. 找到 Motorcomm YT6801 有线网卡。
2. 检查物理链路是 `Up`。
3. 临时配置 `192.168.1.142/24`，不加默认网关。
4. 临时放行来自 `192.168.1.200` 的 TCP 1000。
5. 启动有线 Python 桥接，并打开网页。
6. 退出时移除临时 IP/防火墙规则并恢复原 DHCP。

WLAN 配置全程不变，所以有线接数据时电脑仍可通过另一个 Wi-Fi 上网。

## 切换方案

1. 在当前网页右上角点“关闭服务”。
2. 确认没有进程监听 TCP 1000 / HTTP 8000。
3. 改接网线或切换 Wi-Fi。
4. 启动目标方案的桥接脚本。

两个桥接不能同时运行，因为都需要 TCP 1000、HTTP 8000 和同一个单实例锁。

## 查网卡和地址

```powershell
Get-NetAdapter | Format-Table Name,Status,LinkSpeed,InterfaceDescription
Get-NetIPAddress -AddressFamily IPv4 |
    Format-Table InterfaceAlias,IPAddress,PrefixLength,AddressState
```

## 查端口占用

```powershell
Get-NetTCPConnection -LocalPort 1000,8000 -ErrorAction SilentlyContinue |
    Format-Table LocalAddress,LocalPort,RemoteAddress,State,OwningProcess
```

- `Listen`：某个桥接服务正在监听。
- `Established` 且对端 `192.168.1.200`：CH9121 已连接。
- `TimeWait`：连接刚关闭，这不是仍在监听。

## 为什么直连时保留网关 `192.168.1.1`

CH9121 目标 `192.168.1.142` 和它自身 `192.168.1.200` 在同一 `/24` 子网，会通过 ARP 直接发帧，不使用网关。因此模块中保留无线方案的 `192.168.1.1` 不影响有线直连。

## 直连异常中断后恢复

双击：

```text
有线接收/恢复以太网并切回无线.cmd
```

它只清理有线方案自己的运行状态，不修改 WLAN。
